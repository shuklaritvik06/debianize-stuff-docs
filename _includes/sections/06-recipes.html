Step-by-Step Recipes

Complete workflows for the most common packaging tasks. Copy and adapt these sequences.

Package a new upstream program from scratch

# 1. Download the upstream tarball wget https://example.com/mypkg-1.0.tar.gz # 2. Rename to Debian orig format and unpack cp mypkg-1.0.tar.gz mypkg_1.0.orig.tar.gz tar -xf mypkg-1.0.tar.gz cd mypkg-1.0 # 3. Generate debian/ templates debmake # 4. Edit the required files $EDITOR debian/control $EDITOR debian/copyright dch -v 1.0-1 "Initial Debian packaging" # 5. Build it debuild -us -uc # 6. Check it lintian ../mypkg_1.0-1_amd64.changes debc ../mypkg_1.0-1_amd64.changes

Update a package to a new upstream release

# 1. Download the new tarball (uscan does this automatically) uscan --verbose # 2. Apply it to your existing packaging cd mypkg-1.0 uupdate ../mypkg_2.0.orig.tar.gz # 3. Enter the new directory, fix any patch rejections cd ../mypkg-2.0 dquilt push -a # re-apply patches; fix any .rej files # 4. Update the changelog dch -v 2.0-1 "New upstream release" # 5. Build and test debuild -us -uc lintian ../mypkg_2.0-1_amd64.changes

Add a patch to fix an upstream bug

# 1. Create a new patch slot dquilt new fix-null-ptr-in-parser.patch # 2. Tell quilt about the file you'll change dquilt add src/parser.c # 3. Edit the file $EDITOR src/parser.c # 4. Capture the diff dquilt refresh # 5. Write a DEP-3 header dquilt header -e # 6. Rebuild debuild -us -uc

Build in a clean chroot before uploading

# Build source-only first debuild -S -sa # Build the .dsc in a clean sid chroot sbuild -d unstable ../mypkg_1.0-1.dsc # Check it passes piuparts piuparts ../mypkg_1.0-1_amd64.deb # Upload dput ftp-master ../mypkg_1.0-1_source.changes
