Patching (quilt)

📌
With 3.0 (quilt) format, patches in debian/patches/ are applied automatically at build time. You manage them with quilt (or the dquilt alias that sets the right QUILT_PATCHES variable automatically).
dquilt new / quilt new Start a new patch
dquilt new fix-crash-no-swap.patch
Creates a new empty patch file and makes it active. Always name patches descriptively — the name is permanent and shows up in the packaging history. You cannot skip this step; dquilt add will fail without an active patch.
dquilt add Tell quilt which file you're about to edit
dquilt add src/main.c dquilt add src/parser.c # multiple files, one patch
Must be called before editing a file so quilt can record the before state. One patch can track multiple files — call dquilt add for each one before editing any of them.
dquilt refresh Save your edits into the patch file
dquilt refresh
After editing tracked files, run this to write the diff into the patch. Run again after any further edits to the same files.
dquilt header -e Write a DEP-3 patch header
dquilt header -e
Opens the patch header in your editor. Required before submitting patches upstream — the header records the description, author, and bug reference.

Full DEP-3 header example

Description: Fix crash when system has no swap partition SwapMeter divides by swap_total without checking for zero. Systems with no swap configured crash htop on startup. Forwarded: https://github.com/htop-dev/htop/issues/999 Author: Ritvik Shukla <ritvik@example.com> Bug-Debian: https://bugs.debian.org/123456 Last-Update: 2026-11-12

Forwarded: values

nonot reported upstream yet — you should
not-neededDebian-specific change, upstream would never want it
https://...reported upstream — link to the issue or PR

The goal is to eventually get every patch merged upstream and delete it from debian/patches/.

dquilt push / pop / series Navigate the patch stack
dquilt push # apply next patch dquilt pop # unapply top patch dquilt series # list all patches in order
Patches apply in the order listed in debian/patches/series, top to bottom, every build. Use push/pop to work on a specific patch or reproduce a bug that only appears with certain patches applied.

When updating to a new upstream release

Run dquilt push -a to re-apply all patches. If a patch can't apply cleanly, quilt writes a .rej file next to the source file containing the hunks that failed. Open the .rej, find where that code moved in the new upstream, apply the change manually, then run dquilt refresh. If upstream already fixed the issue, delete the patch entirely: dquilt delete fix-name.patch.
